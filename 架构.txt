项目架构说明（小马口算）

一、总体概览
- 前端：uni-app（Vue 3 默认，条件编译兼容 Vue2），支持 H5 / App(uni-app) / 小程序多端。位于 `bzd/` 目录。
- 后端：Node.js + Express + Socket.IO + MySQL（Sequelize ORM）。位于 `oral-calculation-backend/` 目录。
- 即时通信：Socket.IO（H5 直接使用 socket.io-client；App 端使用 uni 原生 WebSocket 并按 Socket.IO 协议封装）。
- 认证授权：基于 JWT，前端通过 `token` 存储在 `uni.getStorageSync('token')`，后端 `middleware/auth.js` 负责校验。
- 存储与外部服务：MySQL（用户、错题等数据）；阿里云 OSS（头像等资源上传）。
- 构建与发布：HBuilderX（uni-app）；后端使用 `node server.js` 或 `nodemon`。

二、前端架构（bzd/）
1. 目录结构与核心文件
- `App.vue`：全局样式、状态栏安全区（status-bar）适配、应用生命周期。
- `main.js`：应用入口，初始化 uni-app。
- `pages.json`：页面与路由配置（tabbar：首页/AI/PK/我的；功能页：考试、错题、注册、房间、对战等）。
- `request.js`：统一 HTTP 请求封装（携带 `token`、错误处理、API 路径 `api.*`）。
- `uni.scss`：全局样式变量。
- `pages/`：页面模块
	- `tabbar/index/index.vue`：主页，年级横向滚动、题型模块分页、进入练习导航。
	- `tabbar/ai/ai.vue`：AI 页面（聊天/学情分析/讲解错题/智能出题）。
	- `tabbar/pk/pk.vue`：PK模式选择与创建/加入房间。
	- `tabbar/me/me.vue`：我的/登录注册入口与个人信息展示。
	- `exam/exam.vue`：练习与批改页面，支持后端出题与本地降级出题、倒计时、评分、导出/错题集。
	- `wrongProblems/wrongProblems.vue`：错题集浏览。
	- `register/register.vue`：注册页。
	- `room/room.vue`：PK 等待房间（房主/挑战者、准备状态、倒计时、进入对战）。
	- `comp/comp.vue`：PK 对战页面（实时计分、题目生成、结算与再战）。

2. 关键前端机制
- 登录态校验：除登录/注册外，其他页面在 `onShow` 或 `onLoad` 调用 `checkLogin()`，未登录弹窗并跳转 `me`。
- 状态栏安全区：各页模板首部包含 `<view class="status-bar"></view>`，`App.vue` 动态计算高度，避免与系统状态栏重叠。
- 参数传递与解码：从首页进入 `exam` 时通过 `encodeURIComponent` 传参；`exam.vue` 在 `onLoad` 做多次 `decodeURIComponent` 容错，避免 App 端双重编码导致乱码与题型错配。
- 题型映射：`exam.vue` 的 `problemType` 将首页模块文案映射到后端题型key；未覆盖的旧模块走兼容映射或本地降级生成。
- 出题与批改：
	- 后端出题：`GET /api/problems?type=...&difficulty=...&count=...&grade=...`；`request.js` 统一封装。
	- 本地降级：网络异常时切换到本地生成逻辑，覆盖一至六年级主要题型。
	- 批改：`POST /api/problems/submit` 返回 `summary` 与 `details`，前端展示正确率、细项与导出。
- 导出题目：H5 使用 Blob 下载；App 使用 `plus.io` 写入私有目录；微信小程序使用 `wx.getFileSystemManager`。
- PK 通信：
	- H5：`socket.io-client` 直连。
	- App：`uni.connectSocket`，发送 `40` 握手/`42[event,data]` 事件，手动解析处理。
	- `room.vue` 等待逻辑：接收 `roomCreated`/`playerJoined`/`playerReady`/`startPK`，维护 `players`、`selfIndex`、`bothReady`，进入 `comp`。
	- `comp.vue` 对战逻辑：生成同种子题目、实时分数 `updateScore`（携带 `socketId`），完成时 `playerFinished`，接收 `finalResult` 展示双方结果。

三、后端架构（oral-calculation-backend/）
1. 目录结构与核心文件
- `server.js`：应用入口，Express 初始化、路由挂载、Socket.IO 服务、房间状态管理与结算逻辑。
- `config/database.mysql.js`：MySQL 与 Sequelize 连接配置。
- `middleware/auth.js`：JWT 认证中间件。
- `routes/`：REST API 路由
	- `auth.en.js`：登录/注册/用户信息。
	- `problems.js`：出题与批改接口。
	- `ai.js`：AI相关接口（智能出题/讲解等）。
- `models/`：Sequelize 模型
	- `User.mysql.js`：用户模型。
	- `WrongProblem.mysql.js`：错题模型。
- `services/`：服务层
	- `ProblemService.js`：题目生成与批改逻辑。
	- `AIService.js`：AI 能力封装（聊天/学情分析/错题讲解/智能出题）。
	- `OSSService.js`：阿里云 OSS 上传与访问。

2. Socket.IO 房间与事件（简述）
- 房间结构：`rooms = { roomCode: { players: [ {id,name,avatar,ready}, ... ], scores: {}, finished: {}, finalized, timer, config } }`
- 核心事件：
	- `createRoom(data)`：生成纯数字6位房间号，初始化房主与配置，返回 `roomCreated`。
	- `joinRoom(roomCode, playerData)`：加入房间，广播 `playerJoined`（携带玩家列表与配置）。
	- `playerReady(roomCode)`：更新就绪状态，全部就绪后广播 `startPK` 并启动倒计时。
	- `joinComp(roomCode)`：对战阶段加入；维护在线成员。
	- `updateScore({roomCode, score})`：记录分数并广播给对方 `{socketId, score}`。
	- `playerFinished({roomCode, score})`：标记完成，双方完成或倒计时到期时 `finalizeRoom()`，分别向双方发送 `finalResult`。
	- 再战：`inviteRematch`/`acceptRematch`/`declineRematch` 与 `startRematch`。

四、跨端差异与兼容策略
- 字符编码：App 端可能出现双重 URL 编码（如 `%E4%BA%8C年级`），`exam.vue` 在 `onLoad` 做多次解码容错并记录日志。
- Socket 兼容：App 使用原生 WebSocket + Socket.IO 协议消息（`40` 握手、`42[event,data]` 事件），封装发送与解析，保证与后端一致。
- 状态栏与安全区：通过统一 `status-bar` 占位避免内容与系统UI重叠。
- 题型映射一致性：首页文案→后端题型key 映射集中在 `exam.vue` 的 `problemType`，覆盖别名与旧模块。
- 本地降级出题：网络异常时前端生成题目，避免 App 端无网或接口异常导致空白。

五、数据与安全
- 数据库：MySQL（用户、错题记录、练习提交数据）。
- 认证：JWT；后端 `auth` 路由签发，前端 `request.js` 将 `token` 置于请求头。
- 鉴权：后端中间件校验；前端页级校验阻止未登录用户访问。
- 文件：头像等上传到 OSS（`OSSService`）；前端显示使用 URL。

六、部署与运行
1. 后端
- 开发：
```bash
cd oral-calculation-backend
npm install
node server.js
# 或开发模式
npx nodemon server.js
```

2. 前端
- H5 运行：使用 HBuilderX 运行到浏览器。
- App 打包：HBuilderX 打包（清理 `unpackage/` 缓存后重试）。
- 依赖：`socket.io-client`（仅 H5 使用）；App 端无需此依赖即可通过原生 WebSocket 运行。

七、常见问题与排查
- App 参数乱码：检查是否双重编码；`exam.vue` 已做双解码容错。
- App PK不显示头像/准备：确认前端已使用原生 WebSocket 并解析 `playerJoined`/`playerReady`，后端事件返回结构为对象数组。
- 房间号不一致：确保使用纯数字6位生成逻辑，避免 base36 字母数字混合。
- 分数显示错位：前端以 `selfIndex`/`socketId` 区分“我”和“对手”，不要使用房主/挑战者固定位置。
- 出题错位：确认首页模块名称与 `exam.vue` 的 `problemType` 映射一致；必要时在控制台打印参数与映射结果。

八、后续规划（建议）
- 将 Socket.IO App 端封装抽取为公共模块，减少页面内重复代码。
- 在 `ProblemService` 中对题型 key 建立统一枚举，前后端共享，减少文案映射带来的歧义。
- 增加端到端集成测试（登录、出题、批改、PK 创建到结算）。
- 增加错误上报与日志聚合，便于定位移动端问题。

（本说明根据当前仓库代码结构与近期改动整理，旨在帮助快速理解与排查跨端问题。）
